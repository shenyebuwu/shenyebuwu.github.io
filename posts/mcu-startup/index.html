MCU 启动流程

MCU 上电之后，并不会直接执行我们写的 main()。在应用程序运行之前，硬件、启动代码和运行时库需要先准备好执行环境。

本文以常见的 ARM Cortex-M 微控制器为例，梳理从上电到主循环或任务调度的过程。不同芯片、工具链和启动方案的具体步骤可能不同，实际顺序应结合启动文件、链接脚本和芯片手册确认。

从上电到应用程序

上电或复位
    ↓
根据芯片启动配置选择启动存储器
    ↓
读取初始栈指针与复位处理函数地址
    ↓
进入 Reset_Handler（可能先运行 Boot ROM / Bootloader）
    ↓
系统初始化与 C/C++ 运行时初始化
    ↓
进入 main()
    ↓
裸机主循环 / RTOS 任务调度

Bootloader 并非每个应用都需要。如果芯片先进入厂商 Boot ROM，或者项目使用了固件升级引导程序，还会有选择启动介质、检查应用和移交控制权等步骤。

第一阶段：硬件复位与引导

1. 上电复位

电源达到芯片要求后，上电复位电路会按芯片规定释放复位。复位也可能由外部引脚、看门狗或软件触发。

处理器和外设进入各自规定的复位状态，但不能简单理解为“所有寄存器和 RAM 都被清零”。RAM 的初始内容通常不能依赖，部分备份域或保留区域也可能跨复位保存数据。

2. 读取向量表

在常见 Cortex-M 启动模型中，处理器从启动时映射的向量表读取两个关键值：

向量表偏移内容用途
0x00主栈指针 MSP 的初始值建立初始栈位置，通常指向 RAM 中预留栈区域的顶部
0x04复位处理函数的入口值确定 Reset_Handler 的执行入口

当向量表映射在 0x00000000 时，这两项对应的地址就是 0x00000000 和 0x00000004。0x00000004 是存放入口值的位置，不是 CPU 直接从那里执行应用代码。 Cortex-M 入口值还包含 Thumb 状态信息，不能只把它当成普通数据地址理解。

Flash、系统 ROM 或 SRAM 如何映射到启动区域，由具体芯片的启动引脚、选项字节或其他启动配置决定。

3. 执行 Reset_Handler

Reset_Handler 通常定义在芯片对应的启动文件中，例如 startup_stm32f407xx.s。进入这里后，处理器才开始执行启动代码中的指令。

向量表还保存了异常和外设中断处理函数的入口。启动文件往往提供默认处理函数，应用程序可以按工具链约定提供自己的实现。

4. Bootloader 如何移交应用

如果应用前面有 Bootloader，它通常需要先找到并检查应用镜像，再按芯片和工程约定移交控制权。常见工作包括：

  • 处理已经启用的中断、外设和系统节拍，避免应用启动时继承意外状态。
  • 在处理器支持时，将向量表基址配置为应用的向量表位置。
  • 使用应用向量表中的初始栈指针与复位入口完成跳转。

这一步需要结合具体平台实现。普通的函数调用不能自动完成中断状态、向量表和栈等全部交接工作。

第二阶段：准备 C/C++ 执行环境

启动代码的职责，是让编译后的 C/C++ 程序获得它所依赖的初始环境。这些工作可能由汇编启动文件、SystemInit() 和运行时库共同完成。

1. 系统级初始化

根据芯片需求，初始化过程可能包含时钟、FPU、外部存储器或其他底层配置。CMSIS 工程通常提供 SystemInit() 作为系统初始化入口。

初始化顺序取决于启动实现。 有些工程先调用 SystemInit()，再准备 .data 和 .bss；另一些工程由运行时库组织这些步骤。如果此时全局变量尚未初始化，早期初始化代码就不能依赖它们的正常初值。

看门狗也需要按芯片和产品要求处理，可能是喂狗、配置或保持运行，并不是所有启动程序都会关闭它。应用的完整时钟配置也不一定都在启动文件中完成。

2. 复制 .data 段

带有非零初值的可写全局变量、静态变量，通常需要在 RAM 中保存运行时数据，而它们的初始内容保存在固件镜像中。

int counter = 10;
static int mode = 2;

启动过程会根据链接脚本给出的地址，将相应初值从 Flash 等加载区域复制到 RAM 的 .data 运行区域。这样程序开始后，变量既有正确初值，也可以被修改。

3. 清零 .bss 段

未显式初始化或初始化为零的静态存储期对象，通常放在 .bss 中。

int counter;
static int ready = 0;

运行时初始化会将相应区域置零。.bss 通常不需要在固件镜像中存放同样大小的一片零数据，只需记录其位置和大小。

工程也可能定义 .noinit 等特殊区域，用于保留特定数据；这些区域应按链接脚本和启动代码的实际约定处理。

4. 初始化运行时并进入 main

C++ 工程还需要在适当阶段调用静态对象的构造函数。具体工具链可能通过 __libc_init_array()、__main 或其他运行时入口完成相关工作。

这些准备完成后，程序才进入 main()。对于通常不会退出的 MCU 应用，还应明确 main() 意外返回时的处理方式。

第三阶段：应用程序运行

进入 main() 之后，常见的组织方式是裸机超级循环，或由 RTOS 调度多个任务。

模式一：裸机主循环与中断

int main(void) {
    hardware_init();
    application_init();

    while (1) {
        task_A();  // 检查按键或状态
        task_B();  // 更新显示
        task_C();  // 处理接收缓冲区中的数据
    }
}

上面的函数名用于说明结构，具体初始化与任务由应用实现。主循环中的任务依次执行，因此每项工作都应尽量短小，避免长时间阻塞后续处理。

中断用于响应外设事件：当中断使能、屏蔽状态和优先级条件允许时，处理器保存必要现场，进入中断服务程序，完成后恢复此前的执行。

中断服务程序通常只完成及时处理、记录状态或搬运少量数据，再由主循环完成较长的工作。主循环和中断共享数据时，还需要考虑访问原子性和同步。

在常见的“前后台系统”叫法中，中断服务程序属于前台，主循环属于后台。裸机系统也可以满足严格的实时要求，关键在于最坏执行时间、中断延迟和整体设计，不能只用“有没有 RTOS”判断实时性。

模式二：RTOS 任务与调度器

RTOS 将不同功能拆分为任务，由调度器按配置决定哪个就绪任务获得 CPU。下面用 FreeRTOS 风格代码说明结构，省略了完整的错误处理和硬件实现。

#include "FreeRTOS.h"
#include "task.h"

void hardware_init(void);

static void KeyTask(void *arg) {
    (void)arg;
    for (;;) {
        // 检查按键，或改为等待队列 / 通知
        vTaskDelay(pdMS_TO_TICKS(20));
    }
}

static void DisplayTask(void *arg) {
    (void)arg;
    for (;;) {
        // 更新显示
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void) {
    hardware_init();

    // 示例栈深度以 StackType_t 为单位，须按实际任务需求评估。
    if (xTaskCreate(KeyTask, "Key", 256, NULL, 2, NULL) != pdPASS ||
        xTaskCreate(DisplayTask, "Display", 256, NULL, 1, NULL) != pdPASS) {
        for (;;) { /* 处理任务创建失败 */ }
    }

    vTaskStartScheduler();

    // 正常启动后不会返回；返回时应处理启动失败。
    for (;;) { }
}

vTaskDelay() 的参数单位是系统节拍 tick，不能直接把数值当成毫秒。pdMS_TO_TICKS() 根据配置的节拍频率换算，实际时间精度仍受节拍分辨率影响。

在启用抢占的典型单核配置下，更高优先级的任务就绪后，会在调度条件允许时抢占当前低优先级任务。临界区、中断屏蔽和调度器挂起等因素仍然影响响应时间。

任务通过队列、信号量、互斥锁或通知等机制协作。RTOS 提供了组织多任务的工具，但系统是否满足截止时间，还需要结合优先级、执行时间和资源竞争进行分析。

两种应用结构的对比

特性裸机超级循环典型抢占式 RTOS
核心结构主循环与中断任务、调度器与中断
调度方式主循环按应用逻辑执行，中断可打断就绪任务按优先级等规则获得 CPU
实时性取决于循环周期、中断和工作负载取决于优先级、调度延迟和资源竞争
代码组织适合小型系统，也可通过状态机模块化方便拆分相对独立的并发工作
资源开销通常较小需要内核、任务栈等额外资源
选择依据功能复杂度、响应要求与维护成本并发需求、资源预算与时序要求

阅读工程时可以从哪里入手

要把这条启动链路对应到实际工程，可以依次查看：

  1. 芯片启动配置：确认复位后选择哪一块存储器。
  2. 向量表与启动文件：找到初始栈指针和 Reset_Handler。
  3. 链接脚本：确认 Flash、RAM、栈、.data 与 .bss 的位置。
  4. SystemInit() 与运行时入口：确认时钟、内存和构造函数的初始化顺序。
  5. main() 与调度器入口：确认应用如何初始化、如何进入持续运行状态。
